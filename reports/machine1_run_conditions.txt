Order of this run
  1. local_python\build_uk_panel.py
     Read-only pass over pp-complete.csv.
     Keep a row only when price is positive, the date parses, and property type is D, S, T, F, or O.
     Price Paid categories A and B are both kept.
     A row with record status D would be dropped. If none are present, the kept count should stay 31,702,685.
     County labels such as TORBAY.1 have the trailing .number removed.
  2. sh parallel\run_choose_k_by_size.sh, which runs local_python\choose_k_by_size.py
     Python only. No Spark and no MapReduce.
     Sizes: 200000, 1000000, 5000000, 10000000, 20000000, and every row.
     For each size, k = 2..8, n_init = 10, max_iter = 300.
     The fit uses every row of that size. Silhouette uses 30,000 rows drawn from that fit.
     The k used later is the winner on the tag "all", not the winner on 200,000 rows.
  3. Set K in parallel\fair_config.env to that full-file winner.
     The file currently says K=3. That value is only the old 200,000-row silhouette result
     (k=3 score 0.325, k=4 score 0.234). Engines are not timed while K is still 3.
  4. python parallel\prepare_fair_inputs.py once.
  5. Time one Lloyd update on the shared rows, shared k, and shared initial centres.
     Stop when the largest centre movement is at most 1e-4. max_iter 300 is only a cap.
     Python may run on this machine.
     Spark, if installed here, uses local[*]. That is not a YARN submission.
     Hadoop Streaming MapReduce is the job that goes through YARN.
     Each result must record wall-clock time, this CPU, the core count, and this memory
     under data\processed\fair_timing\<hostname>\.
